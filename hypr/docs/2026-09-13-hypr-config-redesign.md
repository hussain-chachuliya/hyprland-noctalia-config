# Hyprland Config Redesign — Explicit Dependencies, Layered Overrides

**Date:** 2026-09-13
**Status:** Approved design (sections 1–6)
**Approach:** A — require/return tables (`local V = require("config.variables")`), explicit three-layer override ordering, windowrules split.

## Problem

The config is split one-file-per-concern, but maintainability is undermined by three issues:

1. **Bare globals as the implicit contract.** `TERMINAL`, `MONITOR1`, `NUM_WPM`, `CACHYGREEN`, `MOD_KEY`, etc. are unqualified globals. Files depend on a hidden load order (`variables` before `binds`, `colors` before `decorations`). Reordering `hyprland.lua` silently breaks behavior, and nothing states a file's dependencies.
2. **Generated tool files mixed with hand-edited files, with no stated override chain.** `hyprland-gui.lua` (HyprMod) re-sets values already set by `inputs.lua`/`decorations.lua`/`misc.lua`; `noctalia.apply_theme()` re-sets colors last. Which file "wins" is accidental.
3. **`windowrules.lua` is a 110-line single file** covering six unrelated rule categories — the same problem `binds.lua` had before it was split.

## Goals (agreed)

- Modules declare their own dependencies via `require` of returned tables.
- Load order stops mattering for correctness.
- Tool-generated overrides are explicitly layered and documented.
- `windowrules.lua` is split by category like `binds/`.
- Value/key names unchanged (mechanical diff, low risk).

## Non-goals

- No auto-discovery / DSL of config modules.
- No renaming of existing keys or semantic values.
- No moving or restructuring `noctalia.lua` / `hyprland-gui.lua` (tools regenerate them at those paths).
- `xdph.conf` untouched.

    ├── misc.lua            # consumes colors

## Dependency contract (core change)

- `config/variables.lua` and `config/colors.lua` stop assigning globals and instead:
  ```lua
  local variables = { TERMINAL = "alacritty", ... }
  return variables
  ```
  using the **same key names** as today.
- Consumers start with an explicit require and qualify references:
  - `config/decorations.lua`, `config/misc.lua` → `local C = require("config.colors")`; `CACHY*` → `C.*`
  - `config/monitors.lua`, `config/workspaces.lua`, `config/binds/*` → `local V = require("config.variables")`; references → `V.*`
  - `config/windowrules/apps.lua` → `local V = require("config.variables")` for `PRIMARY_MONITOR`
- Consequence: `hyprland.lua` require order is cosmetic for the base layer. A new module = create file + one manifest line. Missing deps fail loudly with a traceback naming the module.

## windowrules split

Current `config/windowrules.lua` (110 lines) → four modules:

- **`global.lua`** — generic floating + center rule (line 4); opacity overrides for firefox/zen, terminals, media players (lines 64–69); `suppress-maximize-events` (lines 91–96); `fix-xwayland-drags` (lines 98–109).
- **`apps.lua`** — PiP rule (lines 6–13); per-app rules (lines 48–62: calc, launchers, discord/vesktop, dolphin, ark, keditfiletype, satty, noctalia settings).
- **`gaming.lua`** — full gaming block (lines 15–46): `gamingApps`, `gamingWorkspace`, steam rules.
- **`floats.lua`** — `floatApps` + `modalMatches` loops (lines 71–89).

Rule registration API unchanged (`hl.window_rule`). `gaming.lua`/`floats.lua`/`global.lua` need no deps; `apps.lua` requires `config.variables` for `PRIMARY_MONITOR`.

`config/windowrules.lua` is deleted.

## Override contract (layers)

`hyprland.lua` loads in three documented layers:

```
Layer 1 — Base config (hand-edited, this repo)      → config/*
Layer 2 — Tool-managed overrides (HyprMod GUI)      → require("hyprland-gui")
Layer 3 — Live theme / last word (Noctalia)         → require("noctalia").apply_theme()
```

Rule: **later layer wins where it sets a key.** Consequences spelled out in the manifest comments:
- Noctalia (Layer 3) owns `general.col` and `group.col`; the base palette in `config/colors.lua` is the pre-theme look.
- HyprMod (Layer 2) re-sets rounding/threshold/`natural_scroll`/`ecosystem`/border values that the base layer also sets; where that happens, Layer 2's value is effective until it is changed in the GUI.
- If a setting appears ignored, it is being won by a later layer — this is intentional, now documented.

`hyprland-gui.lua` / `noctalia.lua` are not moved or edited (tools regenerate them).

## Verification

1. `luac -p` syntax-check every `.lua` file.
2. Baseline before changes: `hyprctl binds` and `hyprctl windowrules` counts/lists.
3. After changes: reload config (`hyprctl reload`, or the Noctalia config-reload binding) and compare counts — bind count and window-rule set must be identical.
4. Check `hyprctl configerrors` → expect no errors.

No automated test framework applies to a Hyprland config; the above is the verification suite.

## Rollback

The repo is not under git. Old single files (`config/windowrules.lua`) contain rules preserved verbatim into modules. If a module behaves unexpectedly, each new file is self-contained (one category) and can be inspected/reverted in isolation. A full rollback leaflet: restore `config/windowrules.lua` with its original content and remove the `windowrules/` requires.
