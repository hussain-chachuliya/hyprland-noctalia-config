# Hyprland + Noctalia config

My CachyOS/Arch desktop: [Hyprland](https://github.com/hyprwm/Hyprland) as the
Wayland compositor, [Noctalia](https://github.com/noctalia-dev/noctalia) as the
desktop shell, and [HyprMod](https://github.com/BlueManCZ/hyprmod) for GUI
overrides. Everything is configured in Lua.

**This repository is `~/.config` itself, not a subfolder of it** — that matters
for the install steps below.

---

## Requirements

### Core

```sh
sudo pacman -S hyprland uwsm noctalia
yay -S hyprmod
```

> [!NOTE]
> **Installed CachyOS with its Hyprland-Noctalia edition?** Skip this — the
> `cachyos-hypr-noctalia` metapackage already pulls in `hyprland`, `uwsm` and
> `noctalia` (plus a few of the optional packages below, such as
> `adw-gtk-theme` and `gnome-calculator`). Only `hyprmod` is missing, since it
> comes from the AUR rather than the edition:
>
> ```sh
> yay -S hyprmod
> ```

| Package | Why |
|---|---|
| `hyprland` | the compositor |
| `uwsm` | session manager; `LAUNCH_PREFIX` in `hypr/config/variables.lua` is `uwsm app -- ` |
| `noctalia` | the shell/bar, and the source of the generated theme files |
| `hyprmod` (AUR) | writes `hypr/hyprland-gui.lua` from its settings app |

Not using UWSM? Set `LAUNCH_PREFIX = ""` in `hypr/config/variables.lua` and add
your autostart programs in `hypr/config/autostart.lua` instead of relying on
XDG autostart.

### Apps referenced by keybinds (optional)

All of these are defaults in `hypr/config/variables.lua` — change the string
there if you prefer something else, no other edit needed.

| Variable | Default | Install |
|---|---|---|
| `TERMINAL` | `alacritty` | `sudo pacman -S alacritty` |
| `FILE_MANAGER` | `thunar` | `sudo pacman -S thunar` |
| `BROWSER` | `brave-origin` | `yay -S brave-origin` |
| `EDITOR` | `geany` | `sudo pacman -S geany` |
| `CALCULATOR` | `gnome-calculator` | `sudo pacman -S gnome-calculator` |
| `OPENCODE` | `opencode-desktop` | `yay -S opencode-desktop-bin` |
| `NOTES` | `obsidian` | `yay -S obsidian` |

### Theming (optional)

Referenced by `gtk-3.0/settings.ini` and `gtk-4.0/settings.ini`:

```sh
sudo pacman -S adw-gtk-theme papirus-icon-theme ttf-fira-sans
```

The cursor is a **hyprcursor** theme (`hypr_Bibata-Modern-Ice`, set in
`hypr/hyprland-gui.lua`) living in `~/.local/share/icons/`. No package provides
it — install Bibata yourself if you want the same cursor.

## Repository layout

| Path | What it is |
|---|---|
| `hypr/hyprland.lua` | entry point; requires everything else in layer order |
| `hypr/config/` | Layer 1 — hand-edited base config (binds, rules, monitors, …) |
| `hypr/hyprland-gui.lua` | Layer 2 — generated by HyprMod |
| `hypr/noctalia.lua` | Layer 3 — generated by Noctalia (see [the color filter](#3-enable-the-color-filter)) |
| `hypr/docs/` | design notes for the config |
| `hypr/xdph.conf` | `xdg-desktop-portal-hyprland` screencast settings |
| `noctalia/` | Noctalia settings + sounds |
| `gtk-3.0/`, `gtk-4.0/` | GTK settings; the `noctalia.css` in each is generated |
| `mimeapps.list` | default applications |
| `.gitattributes`, `git-filters/` | keeps generated colors out of the repo |

## How the config layers

From the header of `hypr/hyprland.lua` — later layer wins where both set a key:

1. **Layer 1** — hand-edited base config in `hypr/config/`
2. **Layer 2** — HyprMod GUI overrides (`hyprland-gui.lua`, tool-generated)
3. **Layer 3** — Noctalia live theme (`noctalia.lua`, tool-generated)

Modules self-require their dependencies (`config.variables`, `config.colors`),
so `require` order within Layer 1 is cosmetic.

## Clean setup

### 1. Install the core deps

```sh
sudo pacman -S hyprland uwsm noctalia
yay -S hyprmod
```

CachyOS installed with its Hyprland-Noctalia edition already has the first
three — see [Requirements](#requirements); you only need `hyprmod`.

### 2. Get the repo into `~/.config`

One path works whether or not `~/.config` already exists — git only clones into
an empty directory:

```sh
git clone https://github.com/hussain-chachuliya/hyprland-noctalia-config.git /tmp/dotfiles
cp -a /tmp/dotfiles/. ~/.config/
rm -rf /tmp/dotfiles
```

`cp -a` merges: same-path files are overwritten, everything else already in
`~/.config` is left alone.

Only tracked paths are in the clone. The `.gitignore` ignores everything by
default and whitelists `hypr/`, `noctalia/`, `gtk-3.0/`, `gtk-4.0/` and
`mimeapps.list`, so your other app configs in `~/.config` stay untracked and
never show up in `git status`.

### 3. Enable the color filter

```sh
cd ~/.config
git config filter.noctalia-colors.clean    "$PWD/git-filters/noctalia-clean.sh"
git config filter.noctalia-colors.smudge    cat
git config filter.noctalia-colors.required true
```

Run this from the repo root so the shell expands `$PWD` correctly, and keep the
double quotes — they make the shell substitute the path now rather than storing
the literal string.

**What the three settings do:**

- `clean` rewrites the color block to `rgb(000000)` before git hashes the file,
  so the whole file stays tracked while the wallpaper-dependent colors stay out
  of the repo. Noctalia rewrites that block on every wallpaper change.
- `smudge cat` is an identity filter for the checkout direction. It looks like
  a no-op, but **it is not optional**: with `required = true` and no `smudge`
  program defined, git dies the moment it has to *write* `hypr/noctalia.lua` —
  breaking `clone`, `checkout`, `reset` and `rebase` for that file with
  `fatal: hypr/noctalia.lua: smudge filter noctalia-colors failed`.
- `required = true` makes `git add` fail loudly instead of silently committing
  raw colors when the script is missing.

**If you skip this step:** `hypr/noctalia.lua` shows up as modified after every
wallpaper change, and the raw colors get committed. Since `.git/config` is not
part of the repo, this has to be redone on every clone.

### 4. Start Noctalia

Hyprland autostarts it (`hl.exec_cmd("noctalia")` in
`hypr/config/autostart.lua`); to run it by hand:

```sh
noctalia
```

Noctalia's template processor writes all of these in one pass on each wallpaper
change:

- `hypr/noctalia.lua`
- `gtk-3.0/noctalia.css`, `gtk-4.0/noctalia.css`
- `kitty/themes/noctalia.conf`, `btop/themes/noctalia.theme`,
  `alacritty/themes/noctalia.toml`, `qt5ct/colors/noctalia.conf`,
  `qt6ct/colors/noctalia.conf`

None of them are in git — they're wallpaper-dependent output, so there is
nothing to restore. Until Noctalia has run, `gtk-4.0/gtk.css` imports a
`noctalia.css` that doesn't exist yet and GTK just falls back to the base theme.

### 5. Verify

```sh
git check-attr filter -- hypr/noctalia.lua   # expect: filter: noctalia-colors
git config --get filter.noctalia-colors.smudge  # expect: cat
git status --porcelain                       # expect: no churn from noctalia.lua
hyprctl reload
```

## Tracked vs. generated

| File | Written by | Edit it? |
|---|---|---|
| `hypr/hyprland.lua`, `hypr/config/**` | you | yes |
| `hypr/config/colors.lua` | you | yes — static palette, unrelated to the wallpaper |
| `hypr/hyprland-gui.lua` | HyprMod | no — use the HyprMod settings app |
| `hypr/noctalia.lua` | Noctalia | no — change the theme in Noctalia |
| `gtk-3.0/noctalia.css`, `gtk-4.0/noctalia.css` | Noctalia | no |
| `noctalia/noctalia-config.toml` | Noctalia's settings UI | via the UI |
| `gtk-*/settings.ini`, `gtk-*/gtk.css`, `mimeapps.list` | you | yes |

`hypr/noctalia.lua` is the only generated file that is tracked. That is why it
needs the color filter — every other generated file is simply excluded by
`.gitignore`.
